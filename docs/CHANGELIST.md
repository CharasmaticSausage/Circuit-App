- [ ] **USB4105 footprint fails JLC hole clearance internally** · flaw · fab · 2026-11-02 02:00 · project pcbstudio dev · build 2026-11-02 (seen 1×)
  KiCad's GCT USB4105 footprint has NPTH-to-pad spacing of 0.194 mm, under the 0.25 mm hole_clearance in the jlc_2layer profile. - [ ] **Connector facing is weak on curved outlines** · flaw · placement · 2026-11-02 02:00 · project pcbstudio dev · build 2026-11-02 (seen 1×)
  The edge term pulls a connector's 'front' (courtyard side overhanging its pads) to the nearest outline point, but on circles and ovals it doesn't rotate the part to face outward along the normal, and small ovals leave courtyard overlaps. Add a normal-alignment term, and pre-check area utilisation before placing.
  Evidence: e2e-oval (24 x 18 oval): placement left courtyard overlaps; J1's SH pad broke edge clearance.

- [x] **jlc_search errors on query-only call; requirement not stated until the error fires** · flaw · tools · 2026-11-02 01:15 · project r9-smoke (seen 1×)
  Tool description text says \"`query` words then narrow by MPN or description\" as if query is a standalone narrowing parameter usable on its own, but calling jlc_search(query='USB-C') alone errored: \"give a subcategory (preferred), a category, or a query with a package\". The constraint (query must be paired with package if no subcategory/category given) isn't mentioned anywhere in the tool description, so the only way to learn it is to hit the error.   Status: fixed: requirement stated in the jlc_search description (server/tools.py).

- [x] **set_part_role query word-matching too strict, causes false 0-result for valid subcategory** · bug · data · 2026-11-02 01:15 · project r9-smoke (seen 1×)
  Calling set_part_role with subcategory='USB Connectors' and query='Type-C USB-C receptacle' returned found:0, even though 'USB Connectors' is a valid, populated subcategory (confirmed moments later when the same subcategory with no query returned 100 hits whose category field read exactly 'USB Connectors'). The likely cause is an AND-match requiring every query word to appear verbatim in the part description; 'receptacle' never appears in JLC's descriptions, so the whole query failed silently with no hint which word killed it. Suggest: OR-ranking instead of AND-filtering query words, or at least report which words matched zero parts.
  Status 2026-11-02: fixed: when no part has every word, plain words that no part contains are dropped and named in a note; value words (3.3v, 100nf) are never dropped (server/jlc.py search). Live: 'Type-C USB-C receptacle' in USB Connectors now 85 parts, note 'ignored receptacle'. Test query_drops_only_plain_unknown_words. BUILD_LOG 2026-11-02 (6).
  Evidence: set_part_role(name='USB-C receptacle (5V power in, USB 2.0)', subcategory='USB Connectors', query='Type-C USB-C receptacle') -> {found:0, notes:[\"100 parts came back but none contained every word of 'Type-C USB-C receptacle'\"]}. Re-running with subcategory='usb_c_connectors' as a *category* (not subcategory) and no query returned 100 results including many obviously matching Type-C receptacles.
  Status: partly fixed: the note now names the words no part contained (server/jlc.py search); OR-ranking not done.
